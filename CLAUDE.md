# slsk-mcp

A Soulseek client that runs as a service: it shares a music library, fetches albums into it through sift, and is driven from a web UI or over MCP. It ships as a container image, static Linux binaries and a Windows zip on each GitHub release, and a Pulumi package (`@radiosilence/slsk-mcp-pulumi`, in `deploy/pulumi`) that deploys that image.

## Git

- Small changes may be pushed straight to main; anything larger, and anything touching workflows, goes through a PR. PRs are squashed; merge main into a branch rather than rebasing.
- Releases go through `just release`, never a hand-edited version on main. Never push tags; CI tags and publishes when a release PR merges.
- Commits are signed.

## Changelog

`CHANGELOG.md` is generated by `scripts/changelog.py` and never edited by hand. Every change adds one fragment under `changelog.d/unreleased/<section>/`, named `<pr>-<slug>.md` and holding one `- **Lead.** Detail.` entry; a change pushed to main without a PR names its fragment by slug alone. To correct a note, edit its fragment. `just changelog --stdout` previews the result. The format is in `changelog.d/README.md`.

## Releasing

`just release patch|minor|major` (or an exact `X.Y.Z`) branches from main, bumps the slsk-mcp crate and `Cargo.lock`, `deploy/pulumi/package.json` and its lockfile, and `APP_VERSION` in `deploy/pulumi/src/versions.ts`, turns the unreleased fragments into the version and opens the release PR. The three numbers are one: the package deploys the image by `APP_VERSION`, and CI fails any commit where they disagree. Merging the PR is the release: CI pushes the image's semver tags, then publishes the Pulumi package, then creates the GitHub release with the binaries and the changelog section as notes, so nothing names an image or package that does not exist yet. A push releases only when it changes the version; `gh workflow run ci-cd.yml` on main retries a release that failed part way. The Release workflow (`gh workflow run release.yml -f bump=patch`) opens the same PR from CI.

## CI/CD

`.github/workflows/ci-cd.yml` is one pipeline. CI ends in the `Checks` job, the only status a ruleset should require; CD runs after it on main in the same run and ships what CI built.

The `changes` job decides from the diff which domains a change touches (`rust`, `web`, `package`, `docker`, `deps`) and each CI job runs only for its own, so a skipped job means the change could not affect it and passes `Checks`. `deps` is the exception: main audits every push, since a new advisory can land without any change here; a pull request audits only when it touches a manifest, the lockfile or `.cargo/`. Advisories already in the lockfile are acknowledged in `.cargo/audit.toml`, each with the reason it cannot be fixed yet. Pull requests diff against their base, pushes to main against the last commit whose run passed; a manual run or a release runs everything, as does any change under `.github/`. Markdown counts for nothing. Each domain is an allowlist of paths, so a new top-level directory of code needs adding to the domain that builds it, and a new job needs an `if:` on its domain and a place in `Checks`' `needs`. `changes` also answers once whether the run releases, and every release job reads that answer.

The static binaries are built once per architecture (`linux-build`); the image only copies them in, and a release attaches the same tarballs. Windows is off the release path: the `windows` job lints and tests on pull requests only, and `windows-build` runs only in a release run, with `windows-release` attaching its zip after the release is created, so Windows never delays or blocks a release. CI pushes the image as `:<sha>` on main; CD moves `main` onto it, and a release adds the version tags.

## Check

```sh
just check   # what CI checks bar the audit and release builds: Cargo.lock clean, fmt, clippy -D warnings, tests,
             # the Pulumi package's typecheck, tests and build, a stale assets/app.css, changelog fragments, version agreement, actionlint
just fast    # what the pre-push hook runs
just fmt
just css     # recompile assets/app.css after changing classes in templates or src, or styles/; CI fails if it is stale
```
